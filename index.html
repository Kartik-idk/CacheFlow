The Memory Gap

Modern CPUs execute billions of cycles per second (sub-nanosecond). Reading directly from RAM requires 60–100ns, leaving the CPU idle during memory wait states.

What is Cache?

Cache is small, extremely fast SRAM placed directly on or adjacent to the CPU chip. It stores recently accessed blocks so subsequent requests can be served instantly.

Hit vs Miss Principle

A Cache Hit satisfies the request from SRAM with zero delay. A Cache Miss fetches the data from RAM into cache, replacing old data if full.

Role in Memory Hierarchy

L1 cache is the fastest memory on the processor chip aside from CPU registers. It operates synchronously with the processor core clock frequency. By keeping the hottest loops and variables in L1, the CPU avoids waiting for slower off-chip buses.

💡

OS Concept: Because L1 runs at the processor’s native clock speed, hit rate here directly dictates instruction throughput (IPC).

Core Operating System Principle

Locality of Reference

Caches work efficiently because programs do not access memory randomly. Over 90% of execution time is spent in less than 10% of the code.

Principle 1 Temporal Locality

Recently Accessed Memory is Likely to be Accessed Again Soon

When a variable or instruction is fetched, there is a strong probability the CPU will request the exact same memory address within the next few cycles (e.g. accumulator variables, loop iterators).

C Code Example: Loop Variable C / C++ 
int sum = 0;
for (int i = 0; i < 1000; i++) {
    sum += i; // 'sum' & 'i' accessed 1000 times!
}

Notice how accessing the same address repeatedly results in continuous 100% cache hits after the initial miss.

Principle 2 Spatial Locality

Nearby Memory Locations are Likely to be Accessed Soon

When a program references address k, it will almost certainly reference addresses k+1, k+2 shortly thereafter (e.g. sequential array traversal, linear code execution).

C Code Example: Sequential Array Scan C / C++ 
int arr[100];
for (int j = 0; j < 100; j++) {
    arr[j] = j * 2; // Contiguous adjacent blocks
}

In real hardware, caches fetch full cache lines (e.g. 64 bytes) to capitalize on this spatial proximity.

OS Course Study Guide

Essential Cache Concepts & Theory

Clear, concise textbook summaries covering the foundational questions frequently asked in university Operating Systems and Computer Architecture exams.

01

What is Cache Memory?

Cache memory is an auxiliary high-speed semiconductor memory designed using Static RAM (SRAM). It sits physically closer to the CPU than dynamic main memory (DRAM) and holds duplicate copies of critical instructions and data currently in demand.

02

Why is Cache Memory Required?

This requirement stems from the Memory Wall: processor clock frequencies have scaled exponentially faster than DRAM access speeds. Without cache, modern processors would waste over 80% of their execution cycles waiting idly for RAM data transfers.

03

L1, L2, and L3 Hierarchy

Hardware designers utilize a multi-tier hierarchy: L1 provides instantaneous 1-cycle latency per core; L2 balances size and speed (~4ns); and L3 (Last Level Cache) acts as a large multi-megabyte shared buffer across all active cores before accessing system DRAM.

04

Cache Hit vs. Cache Miss

A Cache Hit occurs when the processor requests a memory address and finds that block currently stored in cache slots. A Cache Miss occurs when the requested address is absent, triggering an eviction and fetch from slower lower-level memory.

05

First-In, First-Out (FIFO) Replacement

When a cache miss occurs and all slots are occupied, the cache controller must decide which entry to evict. Under FIFO, the entry that has resided in the cache for the longest time is replaced first, tracked via a simple circular queue or insertion timestamp.

06

Hit Ratio & AMAT Evaluation

Cache efficiency is quantified by the Hit Ratio: \(\frac{\text{Hits}}{\text{Total Requests}}\). As hit ratio approaches 100%, Average Memory Access Time (AMAT) converges to the ultra-fast cache access time, shielding the CPU from RAM delays.
